# 01 · 准备朋友自己的云主机与 SSH

## 先决条件

你要申请的是**你自己有权使用**的 Linux 云主机/容器实例；至少满足：
- 有外网 TCP 访问能力，可通过 SSH 登录（云厂商可能提供公网 IP 或 **SSH 网关主机名 + 映射端口**）。
- 能出站访问一般 HTTPS/TCP 站点；不是所有免费容器都允许网络代理用途。
- 云厂商条款允许所做的网络转发；机器允许的流量、运行时间、休眠和回收规则要自己确认。

**和本方案相关的服务器配置只有 SSH。** 不需要安装 Xray/VLESS/WireGuard 服务端，不需要在服务器开放 1080 端口。Xray 的 JSON 是**手机端**配置。

## 保存好这四项（保存在自己的私密笔记中，不要提交到 Git）

| 名称 | 示例（都是占位值，不可直接连接） | 从哪里获得 |
| --- | --- | --- |
| SSH 主机地址 | `ssh.example.invalid` | 提供商的 SSH 访问页面 |
| SSH 端口 | `2222` | 提供商的映射端口，可能并非 22 |
| SSH 用户名 | `myuser` | 提供商提供 / 你自己创建 |
| 认证 | SSH 公钥或密码 | 提供商登录方式 |

`ssh.example.invalid` 不是实际服务器。**自己的云主机 IP/SSH 地址只填进 Termius 或 SSH 命令，不需要改 JSON 里的 127.0.0.1。** 后者是手机自身回环地址。

### 原先使用 AL / Altare 类提供商时

即使控制台里显示 `root@sandbox`，也**不等于**应该用 `sandbox` 作为公网 SSH 主机名；必须使用提供商给出的**SSH 网关地址和映射端口**。Web 控制台能打开也不证明外网可通过 SSH 连接。

如服务商提供「Always-on / 保活 / 计划任务」，也不能据此推断免费试用永不回收。**本仓库不安装定时请求、刷活跃度脚本，不规避服务商休眠策略**。

## SSH 安全验收

1. 先用 Termius 或命令行正常 SSH 登录，验证密码/私钥与端口正确。
2. **首次连接核对服务器 host key 指纹**：从服务商管理控制台或独立可信渠道获得并对照；不一致即停止。
3. 如可管理 sshd，优先建立非 root 普通用户 + 公钥认证；只允许需要的用户登录，定期更新系统。
4. **确认允许 TCP 转发**：若服务端禁用了 `AllowTcpForwarding`，则 SSH 登录可成功，但 `-D` SOCKS 代理会失败。
5. 不要把服务端的 1080 端口放到公网防火墙里；`-D 127.0.0.1:1080` 监听的是**手机本地**。

## Termux / Linux 客户端上的等价命令

```bash
ssh -N -D 127.0.0.1:1080 -p 2222 myuser@ssh.example.invalid
```

把示例中的端口、用户名与主机地址换成**自己**的。首次提示确认 SSH 指纹；终端保持连接，没有额外输出通常是正常现象。

使用仓库脚本：

```bash
bash scripts/start-tunnel.sh myuser ssh.example.invalid 2222
```

如果云厂商/系统重启导致 SSH 地址或映射端口变化，需要重新取得连接信息；本仓库不会自动猜测新地址。
